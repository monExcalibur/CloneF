# CloneF

Ассистент отправляет изображение и выбранные лекции в Gemini, показывает ответ и позволяет копировать его или вводить по одному символу на каждое физическое нажатие клавиши.

Новый запуск рассчитан на Ubuntu с Python 3.10+ и поддерживает определение X11/Wayland. Полный сценарий на реальном Ubuntu-десктопе пока не проверен. Проверены логика API, состояние ввода и окно Qt без дисплея; доступ к физическим устройствам, портал GNOME и вставку в целевое приложение необходимо проверить на Ubuntu.

## Установка в Ubuntu

```bash
sudo apt update
sudo apt install python3-venv python3-dev build-essential \
  libxcb-icccm4 libxcb-image0 libxcb-keysyms1 libxcb-render-util0 \
  libxcb-xinerama0 libxcb-xkb1 libxkbcommon-x11-0 libegl1 xwayland
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
```

Откройте `.env` и заполните `GEMINI_API_KEY` собственным ключом. Файл читается как настройки, shell-команды из него не выполняются. Переменные окружения имеют приоритет. Несколько ключей можно указать в `GEMINI_API_KEYS` через запятую. Ключи не передаются в URL и не выводятся приложением в сообщения об ошибках.

`GEMINI_MODELS` задаёт модели через запятую. Доступность моделей зависит от текущего API и вашего проекта; при HTTP 404 приложение пробует следующую модель. Ошибки API выводятся с причиной. Проверка `--doctor` не обращается к Gemini и не подтверждает действительность ключа.

```bash
./start.sh --doctor
./start.sh
```

Также работают `.venv/bin/python -m clonef` и `.venv/bin/python MyAssistant/Assistant.py`.

## Экран и управление

В окне доступны снятие экрана, открытие изображения, загрузка лекций БД/Java и копирование ответа. Они работают без доступа к физической клавиатуре. Лекции берутся из `MyAssistant/` независимо от текущей папки терминала. Другую папку можно задать через `CLONEF_MATERIALS_DIR`.

В X11 захват использует Pillow. В Wayland — `org.freedesktop.portal.Screenshot` через пользовательский D-Bus; GNOME может показать диалог разрешения. Отмена или отсутствие портала выводятся как ошибка. Перед захватом окно ассистента и оверлей скрываются.

Для окна и буфера обмена в Wayland по умолчанию используется Qt/XWayland (`xcb`). Система должна иметь XWayland; снимок экрана при этом по-прежнему запрашивается через портал. Явно заданный `QT_QPA_PLATFORM` сохраняется. Позиционирование и отображение оверлея поверх других окон зависят от оконного менеджера; полный ответ всегда остаётся в основном окне.

При доступной клавиатуре:

| Комбинация | Действие |
| --- | --- |
| Right Shift+P | Снять экран и отправить изображение |
| Ctrl+Shift+D | Загрузить лекции БД |
| Ctrl+Shift+J | Загрузить лекции Java |
| Right Shift+I | Включить ввод или поставить на паузу |
| Esc | Пауза во время ввода |
| Ctrl+Shift+Q | Закрыть приложение |

Вне режима ввода горячие клавиши наблюдаются без блокировки: их символы могут попадать в активное окно. Комбинации обрабатываются по физическим кодам клавиш, независимо от раскладки.

## Ввод по одному символу

Linux-модуль использует `evdev` для чтения и временного захвата физических клавиатур, `uinput` — для виртуального ввода. Он не зависит от X11/Wayland, но требует доступа к устройствам. Настройка ниже предоставляет этот доступ активному локальному пользователю; всё приложение запускается обычным пользователем.

```bash
sudo modprobe uinput
sudo install -m 644 packaging/70-clonef-input.rules /etc/udev/rules.d/70-clonef-input.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=input
sudo udevadm trigger --subsystem-match=misc --sysname-match=uinput
```

После этого выйдите из графической сессии и войдите снова, затем запустите `./start.sh --doctor`. `uinput_writable` и наличие доступных `input_events_readable` проверяются отдельно от готовности GUI. Чтобы модуль загружался после перезагрузки, можно добавить строку `uinput` в `/etc/modules-load.d/clonef.conf`.

Получив ответ, переключитесь в нужное приложение и нажмите Right Shift+I. Альтернатива — кнопка «Начать ввод через 3 секунды»: за это время переключитесь в целевое окно. Сначала отпустите все клавиши; затем каждое нажатие вводит один символ. Удержание клавиши не расходует буфер повторно. Esc или Right Shift+I останавливают ввод и освобождают клавиатуры. Закрытие программы тоже освобождает устройства.

Обычные символы вставляются из буфера обмена через Ctrl+V, переводы строк и табуляции — клавишами Enter/Tab. Это сохраняет Unicode независимо от раскладки. Целевое приложение должно поддерживать вставку; для терминала задайте `CLONEF_PASTE_SHORTCUT=ctrl+shift+v`. Во время ввода содержимое буфера обмена меняется. Вставка в приложение не имеет подтверждения доставки, а автоотступы редактора могут менять результат. Проверьте ввод сначала в обычном текстовом редакторе.

Пауза не пропускает ещё не отправленные символы. Новый ответ отменяет ожидающие шаги старого буфера. Ошибка отправки останавливает ввод. При отключении клавиатуры или потере событий устройства освобождаются; для повторного подключения перезапустите приложение. Подключение новой клавиатуры во время ввода не перехватывается: остановите ввод и перезапустите приложение.

Без прав на устройства приложение остаётся доступным через кнопки и копирование. Если права есть только на чтение клавиатуры, работают горячие клавиши, но ручной ввод остаётся недоступным.

## Проверка без GUI

```bash
./start.sh --image testphoto/photo_2026-04-20_12-57-00.jpg --materials DB
.venv/bin/python -m unittest discover -s tests -v
```

`--image` отправляет указанный файл в настоящий Gemini и требует действительного ключа. Автоматические тесты используют подмену HTTP и устройств, не делают скриншотов и не устанавливают реальные клавиатурные перехваты.

На Ubuntu отдельно проверьте: захват и отмену диалога; загрузку обоих наборов лекций; получение ответа; вставку кириллицы/переносов/табуляций; паузу и возобновление; выход во время ввода; освобождение клавиатуры после отключения устройства.

Для проверки настоящего захвата окна X11 в виртуальном дисплее можно установить `xvfb` и выполнить `QT_QPA_PLATFORM=xcb XDG_SESSION_TYPE=x11 xvfb-run -a .venv/bin/python tests/check_x11_capture.py`. Эта проверка требует Linux/Xvfb и не проверяет физическую клавиатуру, Wayland-портал или настоящий Gemini.

## Старый Windows-запуск

`Start.bat` и `run_temp.vbs` используют прежний Windows-ассистент. `Start.bat` может запускать его из `.venv`, установленного через `python -m venv .venv` и `.venv\Scripts\python -m pip install -r requirements.txt`. Если есть переносной архив `MyAssistant/python.zip`, стартер копирует ассистент, новый модуль `clonef`, лекции и `.env` в папку текущего пользователя `%LOCALAPPDATA%\CloneF`. Новый Ubuntu-запуск этот архив не использует. Windows-код читает общий `.env` и использует исправленный клиент Gemini, но его прежний перехват клавиатуры не проверен и не заменён Linux-модулем.

Строки ключей удалены из резервных Python-файлов, а сохранённый байткод удалён из рабочей копии. Это не удаляет их из истории Git: ранее опубликованные ключи следует отозвать в Google AI Studio. Новые ключи храните только в `.env` или переменных окружения.
